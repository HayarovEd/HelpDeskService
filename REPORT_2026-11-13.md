## 1. Введение и цели работы

## 2. Интеграция веб-виджетов и гостевой авторизации

### 2.1. Устранение блокировок CORS и поддержка внешних виджетов
* **Проблема:** При попытке встраивания виджета обращений с внешних доменов или обращения с локальных dev-серверов (например, React/Vite на `http://localhost:3000`, `http://localhost:5173`) браузер блокировал запросы ошибкой `Invalid CORS request`.
* **Решение:**
  * В [`SecurityConfig.java`](file:///D:/intellig_progects1/HelpDeskService/src/main/java/ru/impuls/helpdeskservice/config/SecurityConfig.java) скорректирована конфигурация `CorsConfigurationSource`: разрешены необходимые паттерны доверенных источников с поддержкой credentials (`allowCredentials = true`), заголовков (`Authorization`, `Content-Type`, `Accept`) и HTTP-методов.
* **Коммит:** `9622b63`

### 2.2. Унификация эндпоинтов гостевой авторизации
* **Проблема:** Клиентские библиотеки и виджеты отправляли запросы как на `/unregistered-login`, так и на `/unregistered_login`.
* **Решение:**
  * В [`AuthController.java`](file:///D:/intellig_progects1/HelpDeskService/src/main/java/ru/impuls/helpdeskservice/auth/controller/AuthController.java) аннотация метода маппинга расширена для поддержки обоих вариантов: `@PostMapping({"/unregistered-login", "/unregistered_login"})`.
  * В [`SecurityConfig.java`](file:///D:/intellig_progects1/HelpDeskService/src/main/java/ru/impuls/helpdeskservice/config/SecurityConfig.java) и [`JwtFilter.java`](file:///D:/intellig_progects1/HelpDeskService/src/main/java/ru/impuls/helpdeskservice/config/JwtFilter.java) добавлены разрешения для путей `/unregistered/**` и `/api/auth/unregistered*`.
* **Коммит:** `9622b63`

### 2.3. Fallback для ролей незарегистрированных пользователей
* **Проблема:** Если в справочнике ролей БД отсутствовала запись `UNREGISTERED_USER`, процесс гостевой авторизации падал с исключением.
* **Решение:**
  * В [`UserHelperServiceImpl.java`](file:///D:/intellig_progects1/HelpDeskService/src/main/java/ru/impuls/helpdeskservice/auth/service/impl/UserHelperServiceImpl.java) реализован автоматический fallback: при отсутствии роли `UNREGISTERED_USER` пользователю безопасно назначается базовая роль `USER`.
* **Коммит:** `9622b63`

### 3.2. Устранение ошибок отображения и XSS-защита
* **Ошибка `escapeHtml is not defined`:**
  * **Проблема:** В консоли браузера возникало исключение `ReferenceError: escapeHtml is not defined`, из-за чего полностью прекращался рендеринг списков пользователей и групп/чатов.
  * **Решение:** Реализована надёжная функция экранирования HTML-спецсимволов в [`home.js`](file:///D:/intellig_progects1/HelpDeskService/src/main/resources/static/js/home.js), предотвращающая XSS-инъекции в именах пользователей, названиях организаций и текстах сообщений.
* **Утечки памяти при предпросмотре изображений:**
  * Для предотвращения накопления неиспользуемых Blob-объектов в оперативной памяти браузера внедрён вызов `URL.revokeObjectURL(url)` после завершения отправки или удаления превью.
* **Корректная работа с `context-path`:**
  * Все API-запросы и WebSocket-подключения в [`home.js`](file:///D:/intellig_progects1/HelpDeskService/src/main/resources/static/js/home.js) адаптированы для автоматического определения префикса `/bc` при развертывании в продакшене.

### 3.3. Новые функциональные возможности панели оператора
1. **Профиль текущего оператора:**
   * В шапку панели добавлен бейдж авторизованного сотрудника с цветным аватаром-инициалом, логином и бейджем роли (`ADMIN` / `OPERATOR`).

## 4. Конфигурация CORS через переменные окружения (.env)

### 4.1. Гибкое управление источниками
* **Проблема:** Жёстко заданный список доменов в исходном коде требовал повторной сборки JAR-архива при добавлении новых клиентских хостов или портов.
* **Решение:**
  * В [`application.yml`](file:///D:/intellig_progects1/HelpDeskService/src/main/resources/application.yml) параметр `application.security.cors-allowed-origins` привязан к переменной окружения `CORS_ALLOWED_ORIGINS`:
    ```yaml
    security:
      cors-allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:3000,http://localhost:5173,http://localhost:8080}
    ```
  * В [`SecurityProperties.java`](file:///D:/intellig_progects1/HelpDeskService/src/main/java/ru/impuls/helpdeskservice/config/SecurityProperties.java) добавлен парсер с автоматической очисткой пробелов и разделением по запятым.
  * В [`SecurityConfig.java`](file:///D:/intellig_progects1/HelpDeskService/src/main/java/ru/impuls/helpdeskservice/config/SecurityConfig.java) единый набор разрешённых origin-паттернов применён для REST API и WebSocket-эндпоинтов `/ws/**`.
  * Создан файл шаблона конфигурации [`.env.example`](file:///D:/intellig_progects1/HelpDeskService/.env.example) и обновлен файл рабочего окружения [`.env`](file:///D:/intellig_progects1/HelpDeskService/.env).
* **Коммит:** `15fe4ea feat(security): allow configuring CORS allowed origins via environment variable`

## 5. Документация для Android-разработки (Ktor Client)

### 5.1. Создание специализированного руководства `ANDROID_KTOR_API.md`
Разработана подробная инструкция [`ANDROID_KTOR_API.md`](file:///D:/intellig_progects1/HelpDeskService/ANDROID_KTOR_API.md), ориентированная на команду мобильной разработки на платформе Android:
1. **Настройка проекта:**
   * Готовые конфигурации `libs.versions.toml` и `build.gradle.kts` для версий Ktor `3.0.x` / `2.3.x` (OkHttp, ContentNegotiation, Kotlinx.Serialization, WebSockets, Logging).
   * Настройка разрешений `INTERNET` и конфигурация `network_security_config.xml` для работы по HTTP/HTTPS.
2. **DTO-модели данных:**
   * Полный набор Kotlin `@Serializable` классов (`AuthResponse`, `UnregisteredLoginRequest`, `ChatDto`, `MessageDto`, `FileDto`, `WsEvent<T>`).
3. **HTTP-клиент (`HelpDeskApiClient`):**
   * Конфигурация движка OkHttp с автоматическим добавлением заголовка `Authorization: Bearer <jwt>`.
   * Реализация сценариев входа: гостевой вход через UUID группы по умолчанию (`00000000-0000-0000-0000-000000000009`), вход оператора.
   * Получение истории сообщений и списка активных чатов.
4. **Multipart-загрузка файлов:**
   * Реализована отправка составных сообщений через метод Ktor `submitFormWithBinaryData`: строго соблюден контракт бэкенда с частью `@RequestPart("data")` типа `application/json` и частью `@RequestPart("files")` с бинарными данными файлов.
5. **Реактивный WebSocket-клиент (`HelpDeskWebSocketClient`):**
   * Получение сообщений в реальном времени через `Flow<WsEvent<MessageDto>>`.
   * Автоматическое переподключение (Exponential Backoff) при разрывах связи и фоновом переводе приложения.
6. **Интеграция Push-уведомлений:**
   * Примеры регистрации push-токенов для Google Firebase Cloud Messaging (`FCM`) и Huawei Mobile Services (`HMS Push Kit`).

### 5.2. Актуализация `API_DOCUMENTATION.md`
* В основной документ [`API_DOCUMENTATION.md`](file:///D:/intellig_progects1/HelpDeskService/API_DOCUMENTATION.md) добавлен раздел быстрых ссылок с прямым указанием на руководство для Android.
